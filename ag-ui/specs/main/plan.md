## Summary

Build the Lynqx Console as a real React/Next.js app. The primary deliverable is the **Copilot screen** — a full-page generative-UI experience where users describe banking tasks in natural language and receive structured, actionable cards. The console shell (sidebar, workspace switcher, header) wraps the screen. Real CopilotKit integration replaces the prototype's mock 700ms timeout. A Zigflow/Temporal `copilot-investigation` workflow backs the `runInvestigation` action, demonstrating the AG-UI ⇄ Zigflow loop explicitly shown in the design's Architecture Strip.

---

**Target Platform**: Desktop browser (Chrome/Firefox/Safari latest), ≥ 1280px
**Project Type**: Web application — Next.js App Router
**Performance Goals**: Starter prompt → card visible < 1s (prototype timeout); real CopilotKit first token < 3s
**Constraints**: Demo scope — no auth, no real banking API, single user

### Phase A: Project Init & Design Token Wiring

**Goal**: Running Next.js app with Lynqx visual design applied.

1. Re-init as Next.js app:
   ```bash
   npx create-next-app@latest . --typescript --tailwind --app --no-src-dir --import-alias '@/*'
   ```

2. Install dependencies:
   ```bash
   npm install @copilotkit/react-core @copilotkit/react-ui @copilotkit/runtime
   npm install @temporalio/client
   ```

3. Copy design tokens into the app:
   - Copy `design/project/lynqx-tokens.css` → `app/globals-tokens.css`

   - Copilot nav item present in all three workspace nav lists
   - Lime checkmark on active route

5. Build `components/shell/Header.tsx`:
   - Port from `design/project/shell.jsx` → `Header` component

   - `.app-shell` → `Sidebar` + `.app-main` → `Header` + `.app-canvas`

**Goal**: Replace mock 700ms delay with real Claude streaming via CopilotKit.

17. Implement `app/api/copilotkit/route.ts`:
    ```typescript
    import { CopilotRuntime, AnthropicAdapter } from "@copilotkit/runtime";
    const runtime = new CopilotRuntime({ /* actions registered here */ });
    export const POST = copilotRuntimeNextJSAppRouterEndpoint({ runtime, endpoint: "/api/copilotkit" });
    ```

18. Wrap `app/layout.tsx` with `<CopilotKit runtimeUrl="/api/copilotkit">`:
    - Import `@copilotkit/react-ui/styles.css`

19. In `CopilotScreen.tsx`, replace the 700ms mock with real CopilotKit:
    - Use `useCopilotChat` (or let `CopilotSidebar` / inline chat handle it) to get streaming responses
    - Map Claude tool calls to GenUI card renders via `useCopilotAction` with `render` prop
    - Persona-aware system prompt sent as `instructions` prop

20. Register `useCopilotAction` for each tool in CopilotScreen:
    ```typescript
    useCopilotAction({
      name: "renderTreasuryPosition",
      description: "Render net USD position card",
      parameters: [{ name: "data", type: "object" }],
      render: ({ data }) => <TreasuryPosition data={data} />,
    });
    ```

21. Register `useCopilotAction` for `runInvestigation` with `renderAndWaitForResponse: true` (the approval gate for `createJiraTicket`).

### Phase D: Zigflow Agent Loop

**Goal**: `runInvestigation` triggers a real Temporal workflow; UI shows live step progress.

22. Implement `lib/temporal.ts` — Temporal client:
    ```typescript
    import { Client, Connection } from "@temporalio/client";
    const connection = await Connection.connect({ address: process.env.TEMPORAL_ADDRESS });
    export const temporalClient = new Client({ connection });
    ```

23. Write `workflows/copilot-investigation.yaml` (full Zigflow DSL — see `contracts/zigflow-workflow.md`)

24. Write `worker/index.ts` — Temporal worker:
    ```typescript
    import { Worker } from "@temporalio/worker";
    const worker = await Worker.create({ taskQueue: "copilot-agents", workflowsPath: "./workflows" });
    await worker.run();
    ```

25. Implement `app/api/agent/start/route.ts`:
    - Parse `{ workflowType, input }` from request body
    - Call `temporalClient.workflow.start(workflowType, { taskQueue: "copilot-agents", args: [input] })`
    - Return `{ workflowId, status: "started" }`

26. Implement `app/api/agent/status/[id]/route.ts`:
    - Describe workflow via Temporal client
    - Return `AgentState` shape

27. Implement `app/api/agent/state-update/route.ts`:
    - Store step updates in server-side Map (keyed by workflowId)

28. In `CopilotScreen.tsx`, after receiving a workflowId from the `runInvestigation` tool call:
    - Poll `/api/agent/status/:id` every second
    - Render an `AgentStatePanel` showing live step names + statuses inside the active AgentCard

## Key Implementation Notes

### Porting the Design

The `design/project/screens-copilot.jsx` is the ground truth. Every visual detail is already specified. Port it JSX-by-JSX into TypeScript React components. Do not redesign — pixel-perfect fidelity is the goal.

Mapping from prototype to real implementation:
- `React.useState` → React hooks (normal imports)
- `window.Icon[name]` → import from `components/shell/Icons.tsx` (port `icons.jsx`)
- `window.CopilotScreen` → export from `components/copilot/CopilotScreen.tsx`
- CSS vars from `styles.css` → copy as a global CSS import (no Tailwind class replacement needed)

### Zigflow ↔ CopilotKit Bridge

The `runInvestigation` CopilotKit action:
1. POSTs to `/api/agent/start` → gets `workflowId`
2. Returns `workflowId` as part of the tool result
3. `AgentStatePanel` polls `/api/agent/status/:workflowId` every 1s
4. Zigflow HTTP callbacks write to `/api/agent/state-update` as steps progress

### No shadcn/ui Needed

The design has its own complete component system (buttons, tags, code blocks, modals) defined in `styles.css` with class names like `.btn`, `.btn-primary`, `.tag`, `.code-block`, `.surface`. Use these directly — no need to install shadcn/ui.

### Font Loading

Use Google Fonts CDN in `app/layout.tsx` (same as `design/project/styles.css`):
```html
<link href="https://fonts.googleapis.com/css2?family=DM+Sans:wght@400;500;600;700&family=DM+Mono:wght@400;500&display=swap" rel="stylesheet" />
```
